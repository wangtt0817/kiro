# MemeMax 主策略：BTC/ETH 永续合约配对交易

> 📌 **这是项目实际采用的策略方案**
>
> 适用环境：MemeMax Perp DEX（纯永续合约，无现货/期权/交割合约）
> 目标：高频交易刷量 + 微利累积 + 严格风控

---

## 一、交易所约束

| 维度 | 限制 | 影响 |
|------|------|------|
| **可用产品** | 仅永续合约（PERP） | 无法做现货+合约对冲、期权对冲、期现基差 |
| **可交易品种** | BTC PERP, ETH PERP | 配对交易的两端 |
| **同品种多空** | 不允许同时持有 | 用 BTC ↔ ETH 跨品种对冲，而非自我对冲 |
| **手续费** | Maker 0.005%, Taker 0.15% | Maker 是 Taker 的 1/30 → 必须全程 Maker |
| **资金费率结算** | 8 小时 | 持仓超 8H 会受 funding 影响，尽量短持仓 |
| **API** | 支持自动化 | 可程序化执行 |

## 三、核心策略：BTC/ETH Ratio 配对交易 ⭐⭐⭐⭐⭐

### 原理

同时做多一方PERP + 做空另一方PERP，赌ETH/BTC价格比率的均值回归。

**关键优势**：纯合约操作，资金利用率极高（可使用杠杆），完美匹配你的交易环境。

### 操作逻辑

```
定义：ratio = ETH_price / BTC_price

监控ratio的Z-Score（偏离均值的程度）

信号1：ratio偏低（ETH相对BTC被低估）
  → 做多 ETH PERP + 做空 BTC PERP

信号2：ratio偏高（ETH相对BTC被高估）
  → 做空 ETH PERP + 做多 BTC PERP

平仓：ratio回归均值
```

### 仓位计算（等金额对冲）

```
假设总资金 = $10,000，使用2x杠杆

方式A：等金额对冲（简单版）
  做多 ETH PERP = $10,000名义价值
  做空 BTC PERP = $10,000名义价值
  保证金需求 = $10,000 / 2（杠杆2x）= $5,000 × 2 = $10,000

方式B：Beta调整对冲（精确版）
  计算beta = 近30天 ETH收益率 对 BTC收益率 的回归系数
  假设beta = 1.3
  做多 ETH PERP = $10,000名义价值
  做空 BTC PERP = $10,000 × (1/beta) = $7,692名义价值
```

### 信号生成（推荐方案）

#### 方法1：简单Z-Score（入门）

```python
import numpy as np

# 计算ETH/BTC ratio
ratio = eth_price / btc_price

# 滚动窗口Z-Score
window = 48  # 48个小时（2天）或 48根K线
ratio_mean = ratio.rolling(window).mean()
ratio_std = ratio.rolling(window).std()
z_score = (ratio - ratio_mean) / ratio_std

# 交易信号
ENTRY_THRESHOLD = 2.0    # 开仓
EXIT_THRESHOLD = 0.5     # 平仓
STOP_LOSS = 3.5          # 止损

if z_score < -ENTRY_THRESHOLD:
    # ratio偏低：ETH被低估
    long_eth_perp()   # 做多ETH
    short_btc_perp()  # 做空BTC
elif z_score > ENTRY_THRESHOLD:
    # ratio偏高：ETH被高估
    short_eth_perp()  # 做空ETH
    long_btc_perp()   # 做多BTC
elif abs(z_score) < EXIT_THRESHOLD:
    close_all()       # 平仓获利

if abs(z_score) > STOP_LOSS:
    close_all()       # 止损
```

#### 方法2：Kalman Filter动态对冲比率（进阶）

```python
# Kalman Filter实时更新 beta（对冲比率）
# 状态方程：beta(t) = beta(t-1) + noise
# 观测方程：ETH_return = alpha + beta × BTC_return + noise

class KalmanPairTrader:
    def __init__(self):
        self.delta = 0.0001  # 状态转移噪声
        self.Ve = 0.001      # 观测噪声
        self.beta = 1.0      # 初始beta
        self.P = 1.0         # 初始不确定性
    
    def update(self, eth_return, btc_return):
        # 预测
        beta_pred = self.beta
        P_pred = self.P + self.delta
        
        # 更新
        y = eth_return - beta_pred * btc_return  # 残差
        S = P_pred * btc_return**2 + self.Ve     # 残差方差
        K = P_pred * btc_return / S              # 卡尔曼增益
        
        self.beta = beta_pred + K * y
        self.P = (1 - K * btc_return) * P_pred
        
        return self.beta, y  # 返回对冲比率和残差（即spread）
```

### 参数建议

| 参数 | 保守方案 | 激进方案 | 说明 |
|------|---------|---------|------|
| K线周期 | 1H | 15min | 更短周期=更多信号但更多噪音 |
| Z-Score窗口 | 72H（72根1H线） | 24H | 窗口太短→过拟合，太长→反应慢 |
| 开仓阈值 | ±2.5 | ±1.8 | 越大越保守 |
| 平仓阈值 | ±0.3 | ±0.5 | 接近0越好 |
| 止损阈值 | ±3.5 | ±4.0 | 太紧容易被震出 |
| 杠杆 | 2x | 3x | 永远不超过3x |
| 单次资金使用 | 总资金20% | 总资金30% | 留足保证金缓冲 |

## 四、辅助方法 A：资金费率差异套利 ⭐⭐⭐⭐

### 原理

即使没有现货，也可以利用**BTC和ETH之间的资金费率差异**获利。

核心思想：
- BTC funding rate = +0.05%（多头付费给空头）
- ETH funding rate = -0.02%（空头付费给多头）
- **做空BTC**（收取0.05%）+ **做多ETH**（收取0.02%）= 每8小时收取0.07%

### 操作逻辑

```
每8小时检查一次（资金费率结算前）：

Step 1：获取BTC和ETH的下一期资金费率（predicted funding rate）
Step 2：计算净收益方向

情况A：BTC_FR > 0 且 ETH_FR < 0
  → 做空BTC PERP（收取BTC资金费）
  → 做多ETH PERP（收取ETH资金费）
  → 双边收费！最佳情况

情况B：BTC_FR > ETH_FR（两者都为正）
  → 做空BTC PERP（收取更高的费率）
  → 做多ETH PERP（支付较低的费率）
  → 净收益 = BTC_FR - ETH_FR

情况C：ETH_FR > BTC_FR
  → 做空ETH PERP（收取更高的费率）
  → 做多BTC PERP（支付较低的费率）
  → 净收益 = ETH_FR - BTC_FR

情况D：两者费率接近或都很小（|BTC_FR - ETH_FR| < 0.01%）
  → 不开仓，观望
```

### ⚠️ 关键风险：方向性敞口

```
问题：做空BTC + 做多ETH ≠ Delta中性！

如果BTC暴涨10%、ETH只涨5%：
  → BTC空单亏10%
  → ETH多单赚5%
  → 净亏5%（远大于资金费率收益）

解决方案：配合核心策略的 ratio 信号

只在以下条件同时满足时开仓：
1. 资金费率差异有利（净收费 > 0.03%/8H）
2. ratio的Z-Score方向与费率方向一致
   例如：做空BTC+做多ETH时，要求z_score < 0（ratio偏低，ETH有回归动力）
```

### 仓位计算

```
关键：必须控制方向性敞口！

方式：等Beta对冲
  假设ETH beta对BTC = 1.3
  如果做多 $10,000 ETH PERP
  则做空 $10,000 × 1.3 = $13,000 BTC PERP
  → 近似消除整体市场方向性风险
  → 剩余敞口：只暴露在ETH/BTC ratio变化

每8小时预期收益：
  净资金费率 × 名义仓位 = 0.03% × $10,000 = $3/次
  每天3次 = $9/天
  年化 = $9 × 365 = $3,285 → 对$10,000资金 = 32.85% APY

但实际收益取决于：
  - 费率差是否持续
  - 方向性亏损是否被控制
```

## 五、辅助方法 B：多时间框架趋势对冲 ⭐⭐⭐

### 原理

利用BTC和ETH在**不同时间框架上的动量差异**：
- 短期（4H）ETH可能跑赢BTC
- 中期（1D）BTC可能跑赢ETH
- 这种差异可以被交易

### 操作逻辑

```
计算两个指标：
  momentum_BTC_4H = BTC当前价格 / BTC 4小时前价格 - 1
  momentum_ETH_4H = ETH当前价格 / ETH 4小时前价格 - 1
  
  relative_momentum = momentum_ETH_4H - momentum_BTC_4H

核心逻辑：
  ETH短期动量 > BTC短期动量（relative_momentum > threshold）
    → ETH在追赶BTC的涨幅 → 做多ETH + 做空BTC（趋势跟随）
  
  或者反向思考（均值回归）：
  ETH短期动量 >> BTC短期动量（overextended）
    → ETH相对BTC涨过头了 → 做空ETH + 做多BTC（均值回归）
```

### 两种模式

```
模式A：动量跟随（趋势型）
  → 哪个近期强就做多哪个，做空弱的那个
  → 适合趋势明显的市场

模式B：动量反转（均值回归型）= 核心策略的变体
  → 近期涨多了的做空，跌多了的做多
  → 适合震荡市

选择建议：
  用ADX（趋势强度指标）判断当前环境
  ADX > 25 → 使用模式A（趋势跟随）
  ADX < 20 → 使用模式B（均值回归）
```

## 六、辅助方法 C：波动率加权动态对冲 ⭐⭐⭐

### 原理

ETH的波动率通常是BTC的1.2-1.5倍。如果不考虑这个差异，"等金额"对冲实际上会暴露方向性风险。

### 操作思路

```
Step 1：实时计算波动率比
  vol_BTC = BTC过去N小时的标准差（年化）
  vol_ETH = ETH过去N小时的标准差（年化）
  vol_ratio = vol_ETH / vol_BTC  （通常1.2-1.5）

Step 2：波动率加权仓位
  如果做多ETH + 做空BTC：
    ETH仓位 = $X
    BTC仓位 = $X × vol_ratio = $X × 1.3（示例）
  
  → 保证两腿的"风险贡献"相等
  → 真正实现风险中性

Step 3：当vol_ratio异常时也可以交易
  vol_ratio历史均值 = 1.3
  当前vol_ratio = 1.8（ETH波动率异常高）
    → ETH波动率可能回落
    → 减少ETH仓位 / 增加BTC仓位
    → 或直接做空ETH + 做多BTC（赌波动率回归）
```

### 原理

资金费率每8小时结算一次，但**预测费率**通常在结算前就可以获取。可以提前布局：

### 操作逻辑

```
资金费率结算时间：00:00, 08:00, 16:00 UTC

策略节奏：
  T-1H（结算前1小时）：查看预测资金费率
  
  如果 预测BTC_FR显著 > 预测ETH_FR：
    → 结算前开仓：空BTC + 多ETH
    → 收取BTC资金费，支付较低ETH资金费
    → 结算后立即平仓或继续持有

  快进快出模式：
    开仓 → 等资金费率结算 → 结算后30min内平仓
    持仓时间极短（1-2小时），方向性风险极低

  预期收益计算：
    假设每次净收费 = 0.02%
    每天3次 = 0.06%/天
    年化 = 21.9%
    
  扣除滑点和手续费后：
    手续费（开+平，双腿）= 4次 × 0.05% = 0.2%
    → 每次净收费必须 > 0.2% 才有利可图
    → 实际只有费率差异大时（>0.05%每边）才值得操作
```

## 九、风险分析（纯PERP环境特有的风险）

### 1. 方向性风险（最大风险！）

```
纯合约环境下，BTC多+ETH空 ≠ 无风险

场景：BTC暴跌30%，ETH暴跌40%
  BTC多单亏损：-30%
  ETH空单盈利：+40%
  净盈利：+10% ✅

场景：BTC暴涨30%，ETH暴涨40%
  BTC多单盈利：+30%
  ETH空单亏损：-40%
  净亏损：-10% ❌

结论：你并非完全对冲，暴露在ETH/BTC ratio变化的风险中。
      这是收益的来源，也是亏损的来源。
```

### 2. 双边资金费率拖累

```
纯PERP没有现货避风港：
  两腿都是合约，两腿都要付/收资金费率

最糟情况：
  你做多ETH + 做空BTC
  ETH funding rate = +0.1%（你做多需要付费）
  BTC funding rate = -0.05%（你做空也需要付费）
  → 每8小时净支出0.15% = 年化 200%+ 的拖累！

应对：
  → 开仓前必须检查两边的资金费率方向
  → 如果两边都对你不利，不开仓
  → 将资金费率纳入开仓决策（辅助方法 A 思路）
```

### 3. 同向强平风险

```
场景：你做多ETH PERP + 做空BTC PERP
  如果整体市场暴涨50%：
    ETH空单不会被强平（你没有ETH空单）
    但如果BTC暴涨导致你的ETH多单保证金不足？
    → 不会，因为ETH也在涨

  真正危险的场景：ETH独立暴跌（BTC不动或微涨）
    ETH多单浮亏严重
    BTC空单没有浮盈来对冲
    → 如果保证金不足 → ETH多单被强平
    → 强平后只剩BTC空单 → 变成纯方向性敞口

应对：
  → 使用逐仓模式（如果MemeMax支持），而非全仓
  → 或确保总保证金远高于最低要求（保证金使用率<60%）
  → 设置价格止损，不依赖强平线
```

### 4. MemeMax特有风险（Perp DEX）

```
作为新上线的DEX（2026年4月），需要注意：
  ├── 流动性不足：大单滑点可能很大
  ├── Oracle风险：价格预言机被操纵/延迟
  ├── 智能合约风险：新平台可能有Bug
  ├── 资金费率机制差异：可能与CEX不同
  └── 交易对手风险：LP池深度有限

建议：
  → 先用极小资金测试（<$500）
  → 确认滑点、手续费、资金费率实际情况
  → 确认是否支持同时开多+开空（不是所有DEX都支持）
  → 了解强平机制的具体规则
```
