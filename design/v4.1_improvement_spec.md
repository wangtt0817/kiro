# VAR-Grid-CV v4.0 → v4.1 全面改进方案

> 本文档针对 [`README.md`](../README.md) 中定义的 **VAR-Grid-CV v4.0（库存驱动的自适应网格做市策略）** 进行系统性改进。
>
> 目标：把一份"骨架清晰、逻辑自洽"的设计文档，升级为"可直接工程化落地"的规范。

## 总览：六大缺陷 × 六份改进

| # | 缺陷领域 | 核心问题 | 改进目标 |
|---|---|---|---|

## A. σ 口径规范

### A.1 为什么先解决 σ

σ 是整套策略的"度量衡"——以下所有模块都直接依赖它：

- 快预警阈值（`k_fast1 * Sigma_short`）
- 慢确认阈值（`k_slow1 * Sigma_mid`）
- AS 中心价偏移（`Volatility²`）
- 网格间距公式（`k1 * Sigma_short_bps`）
- 跳跃检测（"波动率抬升至平时数倍"）

**σ 不定义清楚，所有参数都是浮在空中的。**

### A.2 原文模糊点清单

| 条目 | 原文表述 | 问题 |
|---|---|---|
| σ 时间尺度 | "统一为同一时间尺度下的短周期实现波动率" | 没说这个尺度是 1s / 10s / 1min |
| 快层 σ_short | `k_fast1 * Sigma_short` | 短到多短？用什么价格源？ |
| 慢层 σ_mid | `k_slow1 * Sigma_mid` | 中周期到底多长？和 σ_short 什么关系？ |
| 跳跃态 | "波动率瞬时抬升至平时数倍" | "平时"是哪段？"数倍"是相对谁？ |
| AS 公式 | `Inventory * Gamma * Volatility²` | σ 量纲（年化还是周期内）？ |
| 快预警 spread 基线 | "spread 扩大至近均值的 1.5x-2x" | 均值窗口没定义 |

### A.3 五条硬性设计原则

1. **单一数据源**：所有 σ 都基于 BBO 中点（mid-price），不混用成交价或 microprice
2. **事件驱动 + 定时对齐**：用事件流采样 → 1 秒桶对齐，保证时间轴严格等距
3. **三级分层，尺度递进**：短 / 中 / 长三级，时间尺度呈 ~10 倍递进
4. **bps 统一量纲**：所有 σ 输出统一为"bps / 秒"，不做年化，放大到任意周期只需乘 √n
5. **鲁棒优先**：用 EWMA + MAD 温莎化去极值，不用滚动窗口 std

### A.4 σ 四级分层体系

| 层级 | 半衰期 | 时间语义 | 用途 | 更新频率 |
|---|---|---|---|---|
| **σ_tick** | 无（即时） | 单个 tick | 跳跃检测 | 每 tick |
| **σ_short** | 15 秒 | 10-30 秒视野 | 快预警层阈值基线 | 每快层周期 |
| **σ_mid** | 3 分钟 | 3-10 分钟视野 | 慢确认层阈值基线 | 每慢层周期 |
| **σ_ref** | 1 小时 | 2-6 小时视野 | "平时"基线 / 归一化锚 | 每分钟 |

#### 跨层相对量（z 值）

- `z_short = σ_short / σ_ref` → 快层用，替代"数倍于平时"
- `z_mid = σ_mid / σ_ref` → 慢层用，判断状态切换
- `z_tick = |单 tick 收益| / (σ_short × √Δt)` → 跳跃检测

### A.5 基础数据管道规范

#### 价格源
- 统一用 `(best_bid + best_ask) / 2`，不用 microprice（避免引入 OBI 相关性）

#### 采样方式
- 每收到一次 BBO 更新，覆盖当前 1 秒桶的最新 mid
- 桶结束时取桶内最后一个 mid 作为该秒的收盘价
- 收益率 = `ln(p[t] / p[t-1]) × 10000`，单位 bps/s

#### 为什么是 1 秒桶
- 链上 batch 通常 200ms-2s，1s 桶覆盖 ≥1 个 batch，数据不稀疏
- 所有 σ 都变成"bps per second"，量纲清晰
- 放大到任何窗口只需乘 √(秒数)

### A.6 各级 σ 计算方法

#### σ_short（半衰期 15 秒）
- 方法：对 1s 收益率的平方做 EWMA
- **异常值处理**：代入 EWMA 前，用滚动 60s MAD 截断极端 tick（5 倍 MAD 温莎化），避免 jump 污染短期 σ
- 意义：代表"正常波动"水平，排除 jump 冲击

#### σ_mid（半衰期 3 分钟）
- 方法：同 EWMA，但**不做温莎化**
- 理由：慢层本来就要捕捉波动率结构性变化，不应去极值

#### σ_ref（半衰期 1 小时）
- 方法：同 EWMA，不温莎化
- 额外规则：设下限保护（建议 0.5 bps/s），防止极度安静时 z 值爆炸

#### σ_tick（即时）
- 不预计算；每个 tick 直接用 `|单 tick 收益 bps| / (σ_short × √Δt_sec)` 得到 z_tick
- 若 z_tick > 阈值（建议 6-8），立即触发跳跃事件

### A.7 冷启动（Warm-up）规范

| 条件 | 说明 |
|---|---|
| 运行时间 ≥ 10 分钟 | σ_mid 的半衰期为 3 分钟，10 分钟约 3 个半衰期 |
| 更新次数 ≥ 200 | 保证样本量充足 |
| z_mid ∈ [0.3, 3.0] | 各级 σ 已收敛到合理比例 |

**Warm-up 期内**：
- 允许报价，但所有阈值用保守默认值，不依赖 σ 动态计算
- 网格间距用 `fee×2 + slippage_buffer` 作为下限
- 不允许触发跳跃态以外的状态切换

### A.8 σ 在各模块中的具体应用

#### 快预警层（替代原文"k_fast1 × Sigma_short"）

| 信号 | 归一化方式 | 轻度预警 | 强预警 | 跳跃 |
|---|---|---|---|---|
| 价格斜率 | `(mid - 中枢) / (σ_short × √30s × mid / 1e4)` | 2.0 | 3.0 | 5.0 |
| Spread 异常 | `(spread_now - spread_ewma) / spread_std`（z 值） | 2.0 | 3.0 | — |
| 深度下降 | `(depth_ewma - depth_now) / depth_std`（z 值） | 2.0 | 3.0 | — |

> **核心改变**：原文"1.5x-2x 近均值"这种倍数表达，改为 z 值，不受 σ 绝对水平影响，跨市场/跨波动环境一致。

#### 慢确认层（替代原文"k_slow1 × Sigma_mid"）

| 判定 | 归一化方式 | 进入阈值 | 退出阈值（带滞回） |
|---|---|---|---|
| 价格偏离中枢 | `(mid - 180s_中枢) / (σ_mid × √300s × mid / 1e4)` | z > 2.5 进趋势 | z < 1.0 回震荡 |
| 波动率抬升 | `z_short = σ_short / σ_ref` | ≥ 4.0 触发跳跃条件 | ≤ 1.5 连续 N tick 解除 |

#### AS 中心价偏移

**量纲规范**：`Volatility²` = `(σ_short)² × T_quote`（报价周期秒数），单位是 bps²

**GAMMA 标定方法**（不再拍脑袋）：

> 反推逻辑：希望在"库存恰好触及软限"且"波动率处于正常水平（σ_ref）"时，AS 偏移刚好达到 `AS_SHIFT_CLAMP` 的 50%。

由此得到唯一解：

```
GAMMA = (AS_SHIFT_CLAMP × 0.5 × 1e4) / (INVENTORY_SOFT_LIMIT × σ_ref² × T_quote)
```

不再是"0.02-0.08"的宽区间，而是由 {软限, clamp, σ_ref, 报价周期} 四个已知量反推的确定值。

#### 网格间距

间距公式中的 `Sigma_short_bps` 具体化为：

```
grid_from_vol = k1 × σ_short × √(T_grid_hold)
```

其中 `T_grid_hold` = 一层挂单从挂出到预期成交的平均持有时间（初始建议 60 秒，后续按历史成交频率自适应）。

## B. 参数标定方法论

### B.1 原则：消灭所有硬编码区间

原文的"12%-20%"、"0.02-0.08"等宽区间，全部改为**从少数锚参数推导**的确定值。

### B.2 锚参数（仅需人工设定 5 个）

| 锚参数 | 含义 | 建议值 | 选取依据 |
|---|---|---|---|
| `RISK_BUDGET_DAILY_BPS` | 每日允许的最大亏损 bps | 50-150 | 资金规模 × 风险偏好 |
| `FEE_BPS` | 单边手续费 | 2-5 | 交易所费率表 |
| `TICK_BPS_FLOOR` | 最小 tick 精度 | 1-3 | 合约规格 |
| `MAX_LEVERAGE_CAP` | 最大杠杆 | 3-5x | 风控底线 |
| `SLIPPAGE_BUFFER_BPS` | 滑点缓冲 | 1-3 | 历史成交分析 |

### B.3 衍生参数推导链

```
σ_ref（每日自动标定）
  ├─→ GRID_INTERVAL_BPS = max(FEE×2 + SLIPPAGE, k1×σ_short×√T_hold, TICK_FLOOR)
  │     └─ k1 = RISK_BUDGET / (σ_ref × √86400 × BASE_GRID_ORDERS)
  ├─→ AS_SHIFT_CLAMP_BPS = 2 × σ_ref × √T_quote
  ├─→ AS_GAMMA = (CLAMP×0.5×1e4) / (SOFT_LIMIT × σ_ref² × T_quote)
  ├─→ OBI_ADJUST_CAP_BPS = 0.3 × GRID_INTERVAL_BPS
  ├─→ INVENTORY_SOFT_LIMIT = RISK_BUDGET / (σ_ref × √86400 × MAX_LEVERAGE × 2)
  ├─→ INVENTORY_HARD_LIMIT = SOFT_LIMIT × 2
  └─→ GRID_WIDEN_RATIO = f(z_short)：z_short 越高，间距越宽
```

### B.4 每日标定流程

- 触发时机：UTC 0:00
- 输入：过去 24h 的 1s mid-price 序列
- 输出：更新全部衍生参数到运行时配置
- 约束：衍生参数变动幅度单日不超过 ±30%（防止参数突变导致行为断层）

### B.5 结果：原文参数表改写

| 参数 | 原文 | v4.1 |
|---|---|---|
| `GRID_INTERVAL_BPS` | "动态" | 公式明确，每日标定 |
| `INVENTORY_SOFT_LIMIT` | 12%-20% | 由 RISK_BUDGET + σ_ref 推出唯一值 |
| `INVENTORY_HARD_LIMIT` | 25%-35% | = SOFT_LIMIT × 2 |
| `AS_GAMMA_RISK` | 0.02-0.08 | 反推唯一值 |
| `AS_SHIFT_CLAMP_BPS` | 15-40 | = 2 × σ_ref × √T_quote |
| `OBI_ADJUST_CAP_BPS` | 3-8 | = 0.3 × GRID_INTERVAL |
| `GRID_SHRINK_RATIO` | 30%-70% | 按 z_short 连续映射 |
| `GRID_WIDEN_RATIO` | 1.2x-2.5x | 按 z_short 连续映射 |

## C. 撤补单原子性规范

### C.1 原文缺失

原文只说"撤销冲突挂单"、"补单"，但没有定义：
- 先撤还是先补？
- 撤单确认前老单成交了怎么办？
- 补单和撤单之间的保护窗口是多少？
- 批量撤补时如何排序？

### C.2 风险场景枚举

| 场景 | 描述 | 后果 |
|---|---|---|
| 幻影成交 | 撤单请求已发，但确认回来前老单被成交 | 瞬间库存翻倍 |
| 双重挂单 | 新单先确认，老单后确认撤销（实际未撤） | 同价位双倍敞口 |
| 状态幻读 | 以为撤干净了实际没撤完，基于此报价 | 报价层数溢出 |
| 费用冲击 | 频繁撤补导致链上 gas 支出远超预期 | 侵蚀做市利润 |

### C.3 解决方案：撤补状态机

引入五种挂单生命周期状态：

```
INTENT → PENDING_NEW → ACTIVE → PENDING_CANCEL → DEAD
```

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `INTENT` | 策略决定挂单，尚未发送 | 可取消，不计入敞口 |
| `PENDING_NEW` | 已发送下单请求，等确认 | 计入"乐观敞口"，不可撤 |
| `ACTIVE` | 已收到确认，挂在订单簿上 | 可撤 |
| `PENDING_CANCEL` | 已发送撤单请求，等确认 | 仍计入敞口（防幻影成交） |
| `DEAD` | 已确认撤销或全部成交 | 不计入敞口 |

### C.4 核心规则

#### 规则 1：敞口计算必须包含 PENDING 状态
- 有效敞口 = `ACTIVE` 挂单 + `PENDING_NEW` 挂单 + `PENDING_CANCEL` 挂单中"尚未确认被撤"的部分
- 只有 `DEAD` 状态的挂单才能从敞口中移除

#### 规则 2：先撤后补，不并行
- 模板切换时，执行顺序：
  1. 发送所有需要撤销的挂单的撤单请求
  2. 等待撤单确认（或超时 → 进入防守模式）
  3. 确认完成后，根据"当前真实敞口"重新计算需要补挂的单
  4. 发送补单

#### 规则 3：保护时间窗
- 从"发出撤单请求"到"开始补单"之间，必须等待 `CANCEL_CONFIRM_TIMEOUT`（建议 2-5 秒）
- 若超时仍未收到确认：
  - 标记该挂单为 `PENDING_CANCEL_TIMEOUT`
  - 仍视为有效敞口
  - 不发送新补单
  - 策略降级为"仅去库存"模式直到状态恢复

#### 规则 4：幻影成交处理
- 若 `PENDING_CANCEL` 状态的挂单突然报告成交：
  - 立即将成交量计入库存
  - 重新运行库存制动层
  - 若新库存触发硬限，立即冻结全部新挂单

#### 规则 5：批量撤补排序
- 撤单优先级：离当前 mid 最近的先撤（它被成交的概率最高）
- 补单优先级：离当前 mid 最远的先补（它给策略更多反应时间）

#### 规则 6：撤补频率限制
- 同一价位在 `MIN_REQUOTE_INTERVAL`（建议 3-10 秒）内不允许重复撤补
- 全局每分钟撤补总次数不超过 `MAX_ACTIONS_PER_MIN`（建议 30-60 次）
- 超过限制时策略保持现有挂单不动，仅通过 AS 偏移微调中心价

### C.5 降级矩阵

| 异常情况 | 触发条件 | 策略行为 |
|---|---|---|
| 单笔撤单超时 | `PENDING_CANCEL > CANCEL_CONFIRM_TIMEOUT` | 该挂单标记为"不可控"，仍计入敞口 |
| 批量撤单超时 | > 50% 的撤单请求超时 | 策略进入"冻结模式"，只撤不补 |
| 幻影成交突破硬限 | 幻影成交导致库存直接穿越硬限 | 立即停止所有新挂单，仅保留 TWAP |
| 链上拥堵 | 近 5 分钟平均确认延迟 > 5 秒 | 策略切换为"宽间距低频"模式 |

## D. 快慢层不一致超时处置

### D.1 原文缺失

原文提到 `STATE_MAX_MISMATCH_SEC`（10-20 秒），但**没有定义超时后怎么办**。

### D.2 不一致的四种场景

| 场景 | 快层状态 | 慢层状态 | 含义 |
|---|---|---|---|
| α | 强预警 | 震荡 | 市场可能正在转向但尚未确认 |
| β | 正常 | 趋势 | 市场可能已恢复但慢层尚未降级 |
| γ | 跳跃预警 | 震荡/趋势 | 可能有突发事件但尚未被慢层捕捉 |
| δ | 正常 | 跳跃 | 跳跃已经结束但慢层还在保护 |

### D.3 处置规则：不一致升级梯度

| 阶段 | 持续时间 | 动作 |
|---|---|---|
| 容忍期 | `0 ~ STATE_MAX_MISMATCH_SEC` | 按慢层状态执行，但采用快层的近端微调 |
| 预升级期 | `1x ~ 2x MISMATCH_SEC` | 策略取快层和慢层中**更保守**的一方执行 |
| 强制升级期 | `> 2x MISMATCH_SEC` | 快层直接覆盖慢层的状态判定，相当于"慢层被快层拖走" |
| 异常保护 | `> 3x MISMATCH_SEC` 仍未收敛 | 日志告警 + 策略进入仅去库存模式直到两层重新对齐 |

### D.4 "更保守"的定义

- 震荡 < 弱趋势 < 强趋势 < 跳跃（从左到右越保守）
- 取更保守 = 取更靠右的状态
- 例：快层=强预警（等价弱趋势行为），慢层=震荡 → 预升级期执行弱趋势模板

### D.5 快层拖慢层的约束

- 快层强制覆盖慢层后，必须同时启动一次"慢层加速确认"：把 `STATE_CONFIRM_TICKS` 临时减半
- 若慢层在下一个确认周期内追上快层 → 正常状态切换
- 若慢层在下一个确认周期内仍然不同意 → 快层覆盖失效，回退到容忍期，并记录"误判日志"

### D.6 场景 γ（跳跃预警 + 慢层非跳跃）的特殊处理

- 跳跃预警优先级最高，不等慢层确认
- 快层一旦触发跳跃预警：
  1. 立即执行跳跃模板的"撤近端"动作
  2. 同时向慢层发送"加速确认请求"
  3. 若慢层在下一个周期确认跳跃 → 正式进入跳跃态
  4. 若慢层不确认 → 恢复之前模板，但近端间距扩大一倍作为余震缓冲

## E. 持续单边应对机制

### E.1 原文局限

原文的四层控制在面对持续单边时的最终行为是：停止逆势 → 等待 → TWAP 清洗。

问题：**"等待"是有成本的**——库存浮亏在持续扩大，TWAP 最终还是要在更差的价位出清。

### E.2 改进思路：受控顺势漂移

不做趋势跟踪（那是另一个策略），但允许在**确认趋势后**做有限度的"中心价顺势漂移"，使得：
- 去库存挂单更贴近市场，成交概率更高
- 新增的少量顺势库存（如果有）对冲了部分逆势库存

### E.3 漂移机制定义

**触发条件**：同时满足
1. 慢层确认为强趋势态，且已持续 ≥ 3 个慢层周期
2. 库存处于软限区或硬限区
3. TWAP 已启动但库存改善不足

**漂移规则**：

| 维度 | 规则 |
|---|---|
| 漂移方向 | 仅允许向"趋势方向"漂移中心价 |
| 漂移速度上限 | 每慢层周期最大漂移 = `σ_short × √(SLOW_LOOP_INTERVAL) × 0.5` |
| 累计漂移上限 | 中心价偏离初始入场中枢不超过 `5 × GRID_INTERVAL_BPS` |
| 漂移停止条件 | 库存回落至偏斜区以下 **或** 趋势态退出 |
| 漂移回退 | 趋势态退出后，中心价以每慢层周期 20% 的速度回归 mid |

### E.4 漂移 vs 追涨杀跌的区别

|  | 受控漂移 | 追涨杀跌 |
|---|---|---|
| 目的 | 提高去库存成交概率 | 盈利 |
| 新增仓位 | 不允许增加逆势库存 | 顺势加仓 |
| 累计上限 | 硬上限 `5 × grid_interval` | 无限 |
| 回退机制 | 趋势结束即回退 | 无 |
| 触发前提 | 硬限+TWAP失效 | 信号触发即追 |

### E.5 漂移的附带约束

- 漂移期间 `AS_SHIFT_CLAMP_BPS` 扩大 1.5 倍（允许中心价偏移更大）
- 漂移期间 TWAP 继续运行，两者不互斥
- 漂移导致的成交如果增加了逆势库存 → 立即停止漂移，回退到普通强趋势模板
- 每次漂移的距离和库存变化必须写入日志，供盘后分析

### E.6 策略"盈亏边界"的量化定义

原文缺失"策略在什么样的市场条件下从赚钱变亏钱"的明确界定。补充：

| 指标 | 定义 | 盈亏临界估算 |
|---|---|---|
| 趋势斜率 | `单日累计收益绝对值 / σ_ref / √86400` | `z_daily > 3.0` 时策略大概率亏损 |
| 趋势持续时长 | 连续处于强趋势态的时间 | `> 4 小时` 则库存 TWAP 出清大概率低于成本价 |
| 适用性指标 | 过去 24h `z_daily` | `< 2.0` → 强适用；`2.0-3.0` → 需降频；`> 3.0` → 应暂停 |

建议在每日标定流程中加入"适用性评估"：如果过去 24h 的 z_daily > 3.0，策略次日自动进入"半频运行"（快层周期翻倍、挂单层数减半），直到 z_daily 回落。

## F. 回测与验证框架

### F.1 仿真撮合器架构

| 层级 | 职责 | 说明 |
|---|---|---|
| 数据层 | 提供历史 L2 快照 + 成交流 | 至少 tick 级别，含 BBO、Top10、aggressor |
| 撮合引擎 | 模拟订单簿匹配逻辑 | 按 FIFO + 价格优先；自己的挂单影响深度 |
| 延迟模型 | 注入链上确认延迟 | 从历史 batch 间隔采样（不是固定值） |
| 策略层 | 运行完整 VAR-Grid-CV | 输入=已确认状态，输出=挂单/撤单指令 |
| 评价层 | 计算性能指标 | 见 F.3 |

### F.2 延迟建模方式

- 不用固定延迟（如 1 秒）
- 从历史数据中提取 batch 间隔分布（如 P50=0.8s, P90=2.5s, P99=8s）
- 每次撤补操作随机采样一个延迟值
- 额外模拟"链拥堵事件"：以一定概率（如 2%/小时）注入一次 10-30 秒的延迟脉冲

### F.3 评价指标体系

| 类别 | 指标 | 说明 |
|---|---|---|
| 收益 | 净 PnL（bps/day） | 扣除手续费、gas、资金费率 |
| 收益 | Sharpe Ratio（日频） | > 2.0 视为合格 |
| 风险 | 最大回撤（bps） | 区分已实现/未实现 |
| 风险 | 最大单边库存占比 | 峰值不应超过硬限 |
| 风险 | 库存硬限触发频率 | 每天 < 3 次视为健康 |
| 效率 | 双边成交率 | = 双边对冲的成交量 / 总成交量 |
| 效率 | 平均持仓时长 | 越短说明均值回归越有效 |
| 效率 | TWAP 出清成本 | TWAP 成交价 vs 入场成本的差距 |
| 执行 | 撤补单次数/小时 | 过高说明参数抖动 |
| 执行 | 幻影成交频率 | > 1%/天说明保护窗口不足 |

### F.4 过拟合防范

| 手段 | 具体方式 |
|---|---|
| Walk-forward | 用前 70% 数据标定参数 → 后 30% 验证 |
| 多市场验证 | BTC + ETH + SOL 三个市场跑同一套参数（仅 σ_ref 不同） |
| 参数扰动 | 对所有衍生参数随机 ±20% 扰动，100 次 Monte Carlo |
| 样本外时间段 | 至少留出 1 周完全不碰的数据做最终验证 |
| 极端行情单独验证 | 选取 3-5 次历史大跌/大涨日，观察策略表现 |

### F.5 上线前必须通过的 Gate

| Gate | 条件 | 不通过后果 |
|---|---|---|
| G1 量纲自检 | `σ_short × √86400 ∈ 50-400 bps/day` | 代码 bug，不上线 |
| G2 Walk-forward Sharpe | 样本外 Sharpe > 1.0 | 参数过拟合，重新标定 |
| G3 硬限触发频率 | 回测中 < 5 次/天（95% 分位） | 软硬限设定不合理 |
| G4 最大回撤 | `< RISK_BUDGET_DAILY_BPS × 3` | 风控参数不够紧 |
| G5 延迟鲁棒性 | P99 延迟下仍盈利 | 保护窗口/模板切换太慢 |
| G6 幻影成交冲击 | 幻影成交导致的额外亏损 < 总 PnL 的 10% | 撤补状态机有缺陷 |

## 全局改进总结

| 缺陷 | 原文状态 | v4.1 改进 | 核心收益 |
|---|---|---|---|
| σ 口径 | 未定义时间尺度 | 三级 EWMA + z 值 + 1s 桶 | 所有阈值有量纲、可验收 |
| 参数标定 | 宽区间 | 5 个锚参数 → 全部反推 | 消灭硬编码，自动标定 |
| 撤补单 | 未说明时序 | 五状态生命周期 + 保护窗口 | 防幻影成交、防双重敞口 |
| 快慢不一致 | 超时无处置 | 四阶段升级梯度 | 不再有"知道有问题但不动"的死区 |
| 持续单边 | 只能停、等、TWAP | 受控漂移 + 适用性指标 | 提高去库存成交率，量化策略边界 |
| 回测验证 | 一句话提及 | 完整仿真器 + 指标 + Gate | 工程化落地有据可查 |

## 附录 A：v4.1 验收检查清单（σ 口径专项）

用 ≥ 30 天历史数据回放，验证以下 6 条：

| # | 检查项 | 合格标准 | 不合格说明 |
|---|---|---|---|
| 1 | 量纲自检 | `σ_short × √86400` ∈ 50-400 bps/day | 超出说明 bucket/EWMA 实现有 bug |
| 2 | 稳定性自检 | `σ_ref` 一阶差分绝对值 < 10% × σ_ref | 超出说明 half-life 太短或有污染 |
| 3 | 分布自检 | 标准化后 99% 分位 ∈ [-3, 3]；5σ 外 < 0.1% | 尾部过厚说明 σ_short 低估跳跃 |
| 4 | 跨市场一致性 | BTC/ETH 的 z_short 同时间点相关性 > 0.6 | 否则 σ 有市场特异性噪声 |
| 5 | 冷启动自检 | warm-up 结束时 z_mid ∈ [0.3, 3.0] 命中率 > 95% | 否则 warm-up 期要加长 |
| 6 | 成交率联动 | σ_short 上升期被吃层数同步减少 | 否则 k1 设定过小 |
